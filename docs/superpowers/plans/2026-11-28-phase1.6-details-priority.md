# Awesome Reminder — Phase 1.6 (Task Details, Priority, Reminder Indicator, Pending Badge) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a half-window detail panel (title, priority, due/repeat, tags, Markdown description with inline compressed images), quick priority in the capture box, an eye-catching live reminder indicator while typing, and a red pending-count badge on the taskbar button and tray icon.

**Architecture:** The Go domain grows additively: store migration v2 adds `priority`, `description`, and an `attachments` table, with image files on disk. New core setters back new Wails bindings. A Go asset middleware serves `/att/<id>`. The list window gains an in-page drawer; Markdown libraries are lazy-loaded. A new `internal/badge` package renders the count. On Windows a tiny native window owns the taskbar button and its overlay icon.

**Tech Stack:** Go 1.27 · Wails v3.1.0 · vanilla TS + Vite · `marked` + `dompurify` (exact versions pinned at install) · `golang.org/x/image` (`webp` DecodeConfig, `font/opentype` + `font/gofont/gobold`) · `vitest` + `jsdom` (dev-only, frontend unit tests) · `golang.org/x/sys/windows` (COM/Win32, no CGo)

**Spec:** `docs/superpowers/specs/2026-11-28-task-details-priority-design.md` (with `2026-11-27-awesome-reminder-design.md` and `2026-11-27-ui-design-guide.md`).

**Precondition:** run this plan only after Phase 1 (branch `phase1-local-core`) and Phase 1.5 voice (branch `phase1.5-voice`) are merged into the working branch. Task 6 edits `frontend/src/capture.ts`, which voice also changes. Take the current file as the base and keep the mic button in the right action slot.

## Global Constraints

- No new WebView windows. The panel lives inside the list window. `marked`/`dompurify` are `import()`-ed the first time a panel opens. Idle RAM with the panel closed must not grow; measure as in `docs/manual-test-checklist.md` row 6.
- Priority values are exactly `""`, `"low"`, `"medium"`, `"high"`. Typed tokens: `!high` `!h` `!!!` → high; `!medium` `!med` `!m` → medium; `!low` `!l` → low. A bare `!` or `!!` is text. Tokens inside quotes are text. `Render` emits `!high` / `!med` / `!low`.
- Images: the frontend compresses to longest side ≤ 1600 px, WebP q=0.8, and if > 600 KB retries at q=0.6. It rejects inputs > 20 MB. Go accepts only WebP ≤ 2 MB. Files live at `<DataDir>/attachments/<id>.webp`. Markdown references use the form `![name](att:<id>)`.
- Attachment sweep: tombstone when `unreferenced_since` is more than 7 days old, or when the item has been deleted for more than 30 days.
- Links in Markdown open only `http`, `https` or `mailto`, in the system browser. The webview never navigates. Raw HTML is stripped (DOMPurify).
- Panel width is 50% of the list window, minimum 420 px. When the panel opens in a window narrower than 1100 px, the window widens to 1100 (capped at the screen) and restores on close. Autosave runs after 600 ms idle, and on blur/close/switch.
- Keys:
  - List: click or Enter on a row opens the panel (Enter focuses the title); F2 or double-click on the text does the inline edit; Esc closes the panel, then clears search, then closes the window.
  - Capture: Alt+1/2/3 set High/Med/Low; Alt+0 clears.
  - Editor: Ctrl+B, Ctrl+I, Ctrl+K (link), Ctrl+Shift+C (code), Ctrl+Shift+8 (list), Ctrl+Shift+9 (checklist), Ctrl+S (save now).
- Badge counts every open item (status `open`). Above 9 it shows `9+`; 0 shows no badge. The setting `showPendingCount` defaults to `true`, including for settings saved before this phase. The tray tooltip reads `Awesome Reminder — N pending`, with any hotkey error appended.
- Tokens `--prio-high`, `--prio-med`, `--prio-low` and the light-red reminder accent live in `tokens.css` only, with contrast ≥ 4.5:1 in both themes. Icons are Lucide only. Respect `prefers-reduced-motion`.
- Every new core mutation goes through the existing core write lock, stamps `UpdatedAt`/`UpdatedBy`, and fires `OnChange`.
- Never run `bin/awesome-reminder.exe` from its repo path. Use a copy under `%TEMP%` with `APPDATA` pointed at a temp dir.

## Review Focus

1. **Hostile Markdown.** `<img src=x onerror=alert(1)>`, `[x](javascript:alert(1))`, `<a href="file:///C:/">` must render inert and never navigate. → Task 8 test `sanitizes hostile markdown`.
2. **A huge pasted screenshot** (an 8 MB 4K PNG) must end up ≤ 600 KB and stay usable. A 25 MB input gets the inline message "Image too large (max 20 MB)". → Task 8 tests `compressTarget picks quality step` and `rejects >20MB`.
3. **Priority false positives:** `!important`, `wow!!`, `call Bob !` and `"!h"` stay text. → Task 2 table rows.
4. **Upgrading an existing Phase 1 database:** items, settings and notify log are preserved, new columns get their defaults, and `showPendingCount` defaults to true. → Task 1 `TestMigrateV1ToV2`, Task 9 `TestLoadSettingsMissingShowPendingCountDefaultsTrue`.
5. **An autosave racing a panel switch** (type, then press ↓ within 600 ms) must flush the edit to the original item, not the new one. → Task 7 test `flushes pending edit to the previous item on switch`.
